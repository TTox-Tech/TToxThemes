# TToxThemes — build SPEC (read fully before writing anything)

TToxThemes is a modular glass desktop kit for Debian-family Linux (Kali first), KDE Plasma (5.27 and 6) and
XFCE (4.16+, X11). Three palettes, three performance modes, a top pill bar, a right-edge mini-dock, placeable
desktop widgets, a metrics HUD and a devtools drawer. Everything is generated from `palettes.py` + `tokens.py`.

Repo root: `/home/claude/TToxThemes`. Visual reference (HTML mock of the target desktop):
`/home/claude/ttox-mock/index.html` — read its CSS for exact proportions and colours-in-use.

## 0. Ground rules for every stream

- You own ONLY the paths listed for your stream. Never edit `palettes.py`, `tokens.py`, `build/generate.py`,
  `build/lib.py`, `build/targets/colors.py`, `scripts/lib.sh`, `SPEC.md`, or another stream's files. If you need
  a change in a shared file, write the request in `notes/<your-stream>.md` under "Requests to core".
- There is NO display, compositor, Plasma, XFCE or Kali here. You cannot run the desktop. Never claim something
  was tested on a desktop. Verify what can be verified: `python3 build/generate.py`, `--check`, `bash -n`,
  parsers (configparser, tomllib, json, xml.etree), unit tests with fakes. shellcheck is not installed.
- No colour, size, opacity, font or duration literal in your code if it exists in the palette or tokens: read it
  from `ctx.p`, `ctx.tokens`, `ctx.modes`. Derived shades: use `lib.mix/darken/lighten/over`.
- Python: stdlib only (+ Pillow for wallpaper, + psutil for ttoxd, both optional-import with a clear error).
  Python >= 3.9 compatible (Debian 12 has 3.11; use `tomllib` behind a try/except fallback to a tiny parser if
  you need TOML on 3.9/3.10). Type hints. Deterministic output (sort dict iteration; no timestamps).
- Shell: `#!/usr/bin/env bash`, `set -euo pipefail`, source `scripts/lib.sh`, use `run`, `backup`,
  `install_file`, `install_dir`, `link_file`, `marked_block`, `state_get/set`, `have`, `log/ok/warn/err/step`.
  Every change to a user file goes through those helpers so backup, dry-run and uninstall work.
  Never call sudo silently: print what and why, `confirm`, then `run sudo ...`. No `curl | sh`.
- Capability detection, not distro names. Check `have <cmd>`, versions, files. Degrade by tier:
  Tier 0 colours/fonts/icons -> Tier 1 layout (bar, dock) -> Tier 2 glass (translucency, blur, corners, outline)
  -> Tier 3 motion. An applier that cannot reach the top tier still applies what it can, prints
  `TIER=<n> REASON=<text>` on stdout and exits 10. Exit 0 = full, 1 = failed.
- Third-party components are fetched at install time from pinned upstream URLs listed in `vendor.lock`
  (stream 6 owns the file; put your entries in `notes/<stream>.md` as `name | url | why | fallback`).
  Do not vendor third-party code into the repo. Exception already present: Kvantum's KvFlat SVG may be used as
  a recolour base (GPL-3, keep its notice) — source at `/home/claude/_src/Kvantum/Kvantum/themes/kvthemes/KvFlat/`.
- When done, write `notes/<your-stream>.md`: files written, how each was verified, what could NOT be verified,
  known gaps vs this SPEC, vendor entries, requests to core. Your final message = a short version of that.
- Licence header not required per file; repo is GPL-3.0.

## 1. Generator contract

`build/targets/<name>.py`:

```python
NAME = "kde_colorscheme"     # unique; file name without .py is fine
PACK = "kde"                 # core | kde | xfce | widgets | apps | boot | kali
ONCE = False                 # optional. True: render() called once; iterate ctx.all_palettes yourself
def render(ctx) -> dict[str, str | bytes]: ...   # keys = paths relative to dist/
```

`ctx` (see `build/lib.py::Ctx`): `ctx.name` ("sterling"), `ctx.slug` ("ttox-sterling"), `ctx.title`,
`ctx.p` (palette dict), `ctx.tokens`, `ctx.modes` ({"full","balanced","lite"} -> dict), `ctx.all_palettes`,
`ctx.root`, `ctx.read_src(rel, binary=False)` (reads `src/<rel>`), `ctx.mix`, `ctx.rgba`.
`lib` also has: `hex_to_rgb, rgb_to_hex, darken, lighten, rgb_csv, hex_alpha, over, luminance, contrast,
min_opacity_for_contrast, shift_hue, palette_colors`.

Output path convention: `dist/<pack>/<family>/...` with variant in the name as `ttox-<variant>` and, when the
file differs by mode, `ttox-<variant>-<mode>`. Static assets that need no templating live in `src/<pack>/...`
and are either read by a target or copied by an applier.

Run: `python3 build/generate.py` (all), `--only a,b`, `--check` (determinism), `--list`.

Runtime colours (already generated by core): `dist/core/colors/ttox-<variant>-<mode>/colors.{scss,css,sh,json}`.
At runtime `~/.config/ttox/current` is a symlink to the active one. scss variables: `$bg $surface $raised $line
$muted $fg $fg-hi $accent $accent2 $accent-text $folder $ok $warn $err $glass-term $glass-body $glass-bar
$glass-popup $outline-active $hairline $wash-select $wash-hover $term-0..15 $radius-* $font-mono $font-ui $blur
$graphs`. `colors.sh` exports the same as `TTOX_*`. `colors.json` has everything incl. tokens.

## 2. Runtime layout on the user's machine

- Kit installed to `$TTOX_HOME` = `~/.local/share/ttox` (a copy of this repo incl. `dist/`).
- Config `$TTOX_CONFIG` = `~/.config/ttox`: `state.toml` (flat `key = "value"`: variant, mode, de, packs,
  tier_<pack>, wallpaper, profile, session), `current -> colours dir`, `layouts/<profile>.toml`, `bar.toml`,
  `notes.md`, `backup/<snapshot>/{manifest.tsv,files/...}`.
- Appliers: `scripts/apply_<name>.sh <variant> <mode>`; idempotent; read `$TTOX_DIST`; must work when re-run
  for a live switch (so: fast, no reinstall of packages; package install is the installer's job, the applier
  only checks `have`).
- Metrics: `$XDG_RUNTIME_DIR/ttox/metrics.json` (stream 4 defines schema v1 in `widgets/ttoxd/SCHEMA.md`).

## 3. Design (source of truth for values: tokens.py / palettes.py)

Palettes: Sterling (silver + steel blue), Vino (near-black + wine), Graphite (grey + copper). One grey ramp,
one text pair (`fg`, `fg_hi`), ONE accent (+ `accent2` pressed/inactive selection, `accent_text` = lighter twin
for accent-coloured text on dark). `ok/warn/err` only for status. `folder` = folder icon tint.
Accent may appear only on: selection wash, focus ring, active tab underline, default button, prompt glyph,
focused-app indicator, launcher glyph, toggles that are on, close-button hover uses `err`.

Opacity ladder (`tokens.MODES[mode]`): `term` (terminal, most transparent), `body` (window body == titlebar),
`bar` (top bar, dock), `popup` (menus, launcher, notifications, HUD), `lock`. Surface colours under the alpha:
terminal/bar use `bg`, window body uses `surface`, popups use `raised`.
Blur `blur`/`blur_term` px, `noise`; lite = no blur, no shadows, minimal animation. Mode `off` = compositing off.

Glass edge: active window 2 px outline `fg` @ 60 %, inactive 1 px `line`; bar/dock/popups 1 px `fg` @ 12 %;
titlebar/body separator 1 px `line` @ 30 %. Radii: window 12, pill 16, control 8, selection wash 6, popup 12, menu 8.

Fonts: mono = JetBrainsMono Nerd Font (bar, clock, terminal, window titles, launcher input); UI = Inter
(menus, dialogs, file manager labels). Fallbacks in tokens.

Windows: ONE glass sheet — titlebar same colour+opacity as body. Titlebar 32 px, title left-aligned
`❯ <app>` in mono medium (`❯` in accent_text when active), buttons on the right: maximise, close (thin glyphs,
`muted`; close hover `err`). No minimise by default. Inactive: title `muted`, no accent.
Controls: buttons `raised` + 1 px `line`, radius 8; default button accent fill + `fg_hi`; pressed `accent2`;
inputs `surface` + 1 px `line`, focus 1 px accent ring; tabs underline style (2 px accent under active);
scrollbars 6 px transient `muted` @ 50 %, no arrows; selection = accent @ 28 % rounded 6, text `fg_hi`;
hover = `fg` @ 6 %; sidebars slightly darker than body with 1 px `line` @ 40 % separator.

Terminal: `term` opacity, strongest blur, padding 12, no menubar/scrollbar, tab bar hidden under 2 tabs, block
cursor `fg`, no blink, 16 colours from `p["term"]`, bold is not bright. KDE: Konsole. XFCE: kitty (primary),
xfce4-terminal (fallback).

Top bar: floating pill, height 32, radius 16, 6 px from top, ~85 % of screen width, centred, `bar` glass,
mono 10 pt. Left: launcher/search glyph, overview glyph, workspaces as numbered circles (active = filled `fg`
pill, wider, number in `bg`; others 1 px `muted` outline), date-time `Tue 17 Nov 02:38` in `muted`.
Centre: MPRIS now-playing title (hidden when nothing plays). Right: metrics modules (cpu, ram, net, vpn, docker,
updates; provided by stream 4 as eww or as a text command `ttox-theme --metrics-line <module>`), tray
(monochrome), volume %, brightness %, battery % (hidden without battery), power glyph.

Side mini-dock: right edge, vertically centred, width 54, radius 16, `bar` glass; pinned apps (browser, files,
terminal, editor) icons 28 px; running indicator = 3x12 px bar on the outer edge, `fg` @ 70 %, focused app
`accent`; divider; launcher glyph (accent_text). Dodge windows / autohide.

Desktop: bare clock top-left (mono light 56 pt, `fg_hi` @ 85 %, no frame) and other widgets (stream 4).
No desktop icons by default.

Launcher: Rofi, 560 px, `popup` glass, radius 12, hairline; input row mono; rows 24 px icons, selected row
accent @ 28 %; modes drun/run/window + a power menu script. Notifications: top-right under the bar, 360 px,
`popup` glass, radius 12, 2 px left edge `accent` (normal) / `err` (critical) / `muted` (low), 5 s.

Login/lock: full-screen wallpaper (blurred copy), centred glass card (`lock` opacity over `bg`), mono light
clock 64 pt, avatar, user + password inputs, session/power in `muted` bottom-right.

Hotkeys (tokens.hotkeys): Super+H HUD, Super+grave drawer, Super+space launcher, Super+E widget edit mode,
Super+slash cheatsheet.
